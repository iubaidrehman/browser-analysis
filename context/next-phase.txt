============================================================
OBJECTIVE
============================================================

Upgrade the benchmark so that we can answer:

1. How much total RAM does each architecture actually consume?
2. How does total RAM scale as logical concurrency increases?
3. How many Chromium/browser/renderer processes are created?
4. What is the CPU cost of each architecture?
5. What is the latency/throughput scaling behavior?
6. At what concurrency level does each architecture saturate?
7. How much of the total resource usage is attributable to the
   browser runtime versus the controller/target application?

The benchmark must distinguish:

A. logical-task RSS delta
B. total benchmark architecture RSS
C. browser process-tree RSS
D. target application RSS
E. controller RSS
F. system-wide RSS

3. ADD AGGREGATE RSS
============================================================

At every metrics interval calculate:

    controller_rss
    browser_tree_rss
    target_rss
    auxiliary_rss
    benchmark_total_rss

Definitions:

browser_tree_rss =
    sum RSS of all browser-related processes owned by the benchmark

benchmark_total_rss =
    controller_rss
    + browser_tree_rss
    + target_rss
    + auxiliary_rss

Do not double-count parent/child memory unless the operating-system metric
being used explicitly requires it.

Document exactly how memory is calculated.
